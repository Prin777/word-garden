# 飞牛 NAS 部署

## 使用预打包镜像

如果飞牛终端执行 `uname -m` 显示 `x86_64`，可使用 `word-garden-0.1.0-linux-amd64.tar`。将它上传到解压后的部署包目录，在该目录执行：

```sh
docker load -i word-garden-0.1.0-linux-amd64.tar
docker compose up -d --no-build
docker compose ps
```

应用镜像包含 Node 及运行依赖。Compose 从解压目录的 `data` 加载雅思词库和音频。启动后访问 `http://NAS内网地址:3000`。

## 部署包

将 `word-garden-nas.zip` 解压到 NAS 的持久目录（例如共享文件夹中的 docker/word-garden）。保持 Dockerfile、compose.yaml、public、data 等文件的相对位置不变。data 中带有个人使用的雅思词库与音频，不包含本机用户学习历史。

如需按 NAS 当前架构现场构建，可在 NAS 的终端进入解压目录执行：

```sh
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=50
```

首次构建需要从网络下载 Node 官方基础镜像和 npm 依赖。基础镜像采用支持 amd64/arm64 的 Node 22 Debian slim，NAS 会按自身架构构建。无需在 NAS 安装 Node。

访问 `http://NAS内网地址:3000`。端口冲突时将 compose.yaml 的 `3000:3000` 左侧改为其他端口，例如 `3080:3000`，访问端口也改为 3080。

如使用飞牛的 Compose 项目界面，选择解压后的完整目录及 compose.yaml；若界面不执行 build，请先在终端完成上述 build，再由界面启动同一项目。

## 数据与更新

`./data:/data` 是持久化目录映射。词库、音频、用户和学习记录都在 data 中。删除容器不会删除这个文件夹。

更新代码：保留 NAS 原有 data，替换应用文件后执行 `docker compose up -d --build`。不要用新部署包里的 data 覆盖已有 data，否则可能丢失进度。

备份：执行 `docker compose stop`，复制整个 data 文件夹，再执行 `docker compose start`。恢复也应在停止容器后替换整个 data。

若要迁移电脑已有学习历史：先停止电脑服务，再复制电脑整个 data 到 NAS 的 data；不要在 SQLite 正在写入时只复制 learning.sqlite。

## 导出真正的镜像文件

NAS 构建成功后可导出供相同架构设备导入：

```sh
docker save -o word-garden-0.1.0.tar word-garden:0.1.0
```

目标机器执行 `docker load -i word-garden-0.1.0.tar`，同时复制 data 与 compose.yaml，然后 `docker compose up -d --no-build`。词库不包含在应用镜像里，仍需单独复制 data。

## 公网访问

此版后台没有认证，页面和修改接口均可访问。先在内网试用；公开域名接入和后台访问限制仍按此前约定另行处理。配置 HTTPS 与 IPv6 反向代理时指向 NAS 的服务端口即可，不必让容器直接取得公网 IPv6。
